Memory Management in Operating Systems

1. Introduction to Memory Management

Memory management = the OS job of giving RAM to programs, tracking what is used, and taking it back when done.

Double-click Chrome → OS finds free RAM → copies Chrome from disk into RAM → CPU runs it.

2. Memory Allocation

Fixed partitioning: RAM cut into equal-size slots in advance. Variable partitioning: each process gets exactly the size it needs.

What is happening

Key terms

Internal fragmentation = wasted space inside an allocated block (red stripes).
External fragmentation = free space is scattered in small holes, so a big process can't fit.

Example

Old systems like IBM OS/360 MFT used fixed partitions; MVT used variable ones.

3. Allocation Algorithms

When a process arrives, which free block should the OS choose? Free blocks (KB): 100, 500, 200, 300, 600. Processes: P1=212, P2=417, P3=112, P4=426.

What is happening

Rules

First: first block big enough (fast).
Best: smallest block big enough (least leftover).
Worst: largest block (big leftover stays usable).

4. Paging

Process is cut into equal pages; RAM into equal frames. The page table maps page → frame, so pages can sit anywhere in RAM. Page size = 4 bytes.

What is happening

Move the slider to pick a logical address (0–15). The CPU gives the page number + offset; the page table gives the frame.

Formula

Page = address ÷ page size
Offset = address mod page size
Physical = Frame × page size + Offset

Example

A 16-byte program loaded into scattered frames 5, 2, 7, 0 — no need for 16 continuous bytes.

5. Segmentation

Program is split into logical segments (Code, Data, Stack) of different sizes. Each has a base (start address) and limit (length).

What is happening

Rule

If offset < limit → physical = base + offset.
Otherwise the OS raises a trap (segmentation fault).

Example

Accessing arr[500] of a 300-byte data segment → "Segmentation fault" in C.

6. Virtual Memory

Virtual memory lets a program be larger than RAM by keeping extra pages on disk. Demand paging loads a page only when it is first needed. A missing page causes a page fault.

What is happening

Page fault steps

1. CPU asks for page not in RAM → trap
2. OS finds page on disk
3. Loads it into a free frame
4. Updates page table, retries

Example

A 2 GB game runs on 1 GB free RAM — only the levels you play are loaded.

7. Page Replacement

When RAM is full and a page fault occurs, the OS must evict one page. Goal: fewest page faults. RAM = 3 frames.

What is happening

Algorithms

FIFO: evict the oldest page.
LRU: evict the least recently used.
Optimal: evict the page needed farthest in future (best, but needs future knowledge).

Try this

Run each to the end and compare faults: FIFO 15, LRU 12, Optimal 9.

8. Thrashing

Thrashing = the system spends more time swapping pages in and out than doing real work, because processes don't have enough frames.

RAM = 12 frames. Each process needs 3 frames to run well.
CPU utilization by number of processes

What is happening

Why it happens

Too many processes → few frames each → constant page faults → CPU waits for disk → OS thinks CPU is idle and adds even more processes!

Fix

Reduce the number of running processes, or add RAM.

Summary

Memory management gives every program safe, efficient use of limited RAM.

1. Introduction
OS loads programs from disk to RAM so the CPU can run them.
2. Allocation
Fixed → internal fragmentation. Variable → external fragmentation.
3. Fit algorithms
First (fast), Best (least leftover), Worst (largest block).
4. Paging
Pages → frames via page table. Physical = frame × size + offset.
5. Segmentation
Logical segments with base + limit; offset ≥ limit → trap.
6. Virtual memory
Pages loaded on demand; a missing page = page fault.
7. Page replacement
FIFO, LRU, Optimal decide which page to evict. Optimal is the benchmark.
8. Thrashing
Too little memory per process → endless swapping, CPU utilization collapses.
